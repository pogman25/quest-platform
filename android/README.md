# Android-приложение «Бюро квестов»

Нативное приложение на Kotlin и Jetpack Compose. Ведущий настраивает игру и передаёт тот же телефон команде. Сервер, веб-админка, Node.js и Docker для Android-версии не нужны.

## Сброс отдельной улики и текст NFC-меток

Ведущий открывает «Прохождения команд» и нажимает «Сбросить улику» под нужным заданием начатой команды. После подтверждения удаляются только ответы, время открытия и решения, полученная цифра и счётчик шума этой улики. Кнопка доступна после появления прогресса. Настройки, фотография, ответы-эталоны, калибровка, чувствительность и назначенная цифра замка остаются из текущего прохождения; новые настройки из редактора не подставляются. Команда, общий момент старта и остальные улики сохраняются. Если игра была завершена, она снова становится незавершённой, а общий код скрывается до повторного решения. Сброс архивной команды не переключает текущую команду.

При сканировании неверной или неизвестной NFC-метки игрок видит записанный на ней текст. В редакторе поле «Текст NFC-метки» поддерживает несколько строк — туда можно записать забавную фразу. Верная метка сохраняет прежний экран успеха и выдачу цифры. Неизвестная метка по-прежнему не добавляет попытку, настроенная ложная добавляет неверную попытку. Ошибки чтения и отсутствие текстового содержимого показываются отдельно.

## Полноценный квест «Тихий обыск»

**Сборка `9d0ad6a` без отдельного прототипа шумомера установлена на S10e с сохранением данных; проверен запуск приложения. Калибровка доступна в настройках «Тихого обыска».**

Седьмой тип улики доступен через «Улики и сюжет» → «Добавить улику» → «Тихий обыск». Новые игры сохраняют прежние шесть улик; обыск включается явно, поскольку для него нужна калибровка. В игре теперь допустимо от одной до семи улик, длина кода замка соответствует их числу.

В редакторе ведущий задаёт описание предмета и четырёхзначный код его метки, включая начальные нули. «Калибровка и чувствительность» открывает шумомер: установите телефон в положение для игры, откалибруйте фон, настройте чувствительность и нажмите «Применить к этой улике». Применение меняет черновик; «Сохранить изменения» записывает игру. Сохранение обыска без подходящей калибровки запрещено.

Команда нажимает «Начать / продолжить обыск». После секундной подготовки включается микрофон и начинает отсчитываться время этой улики. Каждое новое превышение увеличивает счётчик и подсвечивает сигнализацию красным на три секунды. Поиск и ввод кода продолжаются. Один длительный шум считается одним событием. В игре доступны счётчик, шкала, остановка и беззвучная цифровая клавиатура; калибровки, изменения чувствительности и сброса счётчика у команды нет.

Правильный код метки выдаёт цифру замка и открывает обычный экран успеха. Проверка кода проходит после свежего кадра микрофона; превышение в этом кадре сохраняется до принятия ответа. Общий способ отправки ответов не позволяет решить обыск без активной сессии микрофона. При выходе, сворачивании, блокировке или повороте микрофон останавливается, а накопленный счётчик остаётся. Для продолжения нужно снова запустить измерение. Состояние продолжающегося шума также сохраняется: повторный вход сам по себе не создаёт новое превышение.

Счётчик виден на экране успеха, в итогах команды и в истории прохождений. В истории есть таблицы завершённых обысков: меньше превышений — выше место, при равенстве сравнивается время в секундах; одинаковые результаты делят место. Сравниваются только прохождения одной игры с одинаковыми описанием, кодом и настройками шумомера. Уже начатый обыск сохраняет свою копию этих настроек при редактировании игры. «Сбросить результаты» у ведущего очищает счётчик вместе с остальными результатами выбранного прохождения, в том числе для удалённой исходной игры.

Room обновлён с версии 1 до 2 миграцией `MIGRATION_1_2`: к `run_quests` добавлены счётчик, состояние срабатывания и время последнего превышения. Игры, пароли, фотографии, ответы и активное прохождение сохраняются. События пишутся транзакционно в момент обнаружения; уже обнаруженное превышение дописывается при уходе с экрана. Разрешение и lifecycle микрофона объединены в `rememberMicrophoneAccess`, устройство используется одним потребителем за раз. Звуковые файлы не создаются.

## Калибровка шумомера

Шумомер открывается из редактора «Тихого обыска» по кнопке **«Калибровка и чувствительность»**. На этом экране ведущий проверяет порог и применяет настройки к улике; тестовый счётчик не меняет результаты команд. Отдельный прототип в каталоге ведущего удалён. При восстановлении старого маршрута приложение возвращается на предыдущий экран.

1. Разрешите микрофон. Поставьте телефон на устойчивую поверхность, не закрывая микрофон, и нажмите «Калибровать фон · 5 с».
2. После секундной подготовки микрофона сохраняйте обычную тишину комнаты 5 секунд. Затем измерение начнётся автоматически. Слишком громкий фон потребует повторной калибровки.
3. Сравните шёпот, разговор, шаги, хлопок и короткий стук. Шкала показывает приближение к порогу; вертикальная черта обозначает порог, цвет и надпись сигнализируют о срабатывании.
4. Настройте чувствительность: справа замечаются более тихие звуки. При смене порога и сбросе счётчика есть 750 мс на затихание касания экрана.
5. Продолжительный шум считается одним событием. Для следующего нужны 600 мс затишья и минимум секунда с предыдущего срабатывания. Кнопка «Сбросить счётчик» сохраняет калибровку и не превращает продолжающийся шум в новое событие.
6. «Применить к этой улике» переносит настройки в черновик. «Остановить измерение» освобождает микрофон, «Продолжить измерение» использует прежний фон. Для новой калибровки сначала остановите измерение. Повторная калибровка обнуляет счётчик; её также стоит повторять после переноса телефона.

Во время измерения экран не гаснет автоматически. При выходе, блокировке, сворачивании или повороте окна захват останавливается; продолжение требует нажатия кнопки. Частичная калибровка отменяется. Фон, чувствительность и счётчик живут во ViewModel: переживают поворот, но не закрытие процесса. При выключенном доступе к микрофону в Android или занятом входе показывается ошибка. Фоновая служба не используется.

`MicrophoneMeter` читает встроенный микрофон через [AudioRecord](https://developer.android.com/reference/android/media/AudioRecord): PCM16, моно, 44,1 кГц, окна по 50 мс. При поддержке выбирается `UNPROCESSED`, иначе `VOICE_RECOGNITION`; фактический режим виден в «Показаниях микрофона». Аудиобуфер обрабатывается в памяти, аудиофайлы не создаются. Экран показывает dBFS — цифровой уровень, который не является измерением физических дБ SPL.

`domain/NoiseDetector.kt` содержит чистые вычисления RMS/пика, калибровку по 75-му процентилю, пороги и повторное взведение. Чувствительность задаёт запас 6–24 дБ над фоном; для краткого пика добавляется 6 дБ, для среднего уровня нужны 100 мс превышения. Пороги ограничены достижимым цифровым уровнем. Гистерезис 3 дБ и интервал тишины объединяют один шум и его эхо в событие. `NoiseMeterViewModel` связывает поток с состоянием; `navigation/NoiseMeterContent.kt` подключает разрешение и lifecycle, как React effect с cleanup, а `NoiseMeterScreen` и `NoiseLevelCard` рисуют состояние. `AudioRecord` освобождается в `finally`, новый запуск ждёт завершения предыдущего.

## Этап 4: отдельные редакторы и печатный реквизит

Карточка игры открывается одной кнопкой «Открыть игру». Внутри один экран с разделами «Улики и сюжет» и «Команда и запуск»: общие настройки, отдельные редакторы улик и подготовка команды находятся в одном месте. Команда и код не теряются при переключении разделов и возврате из редактора улики. «Сохранить игру» сохраняет изменения и оставляет экран открытым; «Передать команде» сначала сохраняет настройки, затем создаёт прохождение и открывает инструктаж. Отдельного экрана «Подготовить игру» больше нет. История и правила раскрываются отдельно, позиции улик меняются перетаскиванием за значок в заголовке карточки. Кнопки «Настроить» и «Убрать» размещены в одной строке. Каталог поддерживает поиск и создаёт только видимые карточки.

Перетаскивание начинается сразу за значок из шести точек справа в заголовке улики. Переносимая карточка выделяется цветом и тенью, остальные плавно сдвигаются; у края списка включается прокрутка. Короткое нажатие на значок открывает компактное меню «Переместить выше/ниже», доступное также с TalkBack и клавиатуры. Порядок меняется в черновике и сохраняется вместе с игрой; он задаёт позиции цифр в коде. Для жестов, анимации и прокрутки используется [Reorderable 3.1.0](https://github.com/Calvin-LL/Reorderable/tree/v3.1.0), порядок хранит прежняя ViewModel. Список использует стабильные ключи типа улики — аналог `key` в React. **Сборка `5433698` с перетаскиванием и кнопками в одну строку установлена на S10e без очистки данных; проверен запуск приложения.**

Добавлены подготовка и сохранение реквизита:

- **QR-пазл:** размер 120/150/180 мм, заполнение квадрата или снимок целиком, предпросмотр обеих сторон и PDF из двух страниц A4 для двусторонней печати по длинному краю. На лицевой стороне сетка 3×3, на обороте QR с коррекцией H, полями и тем же центром. Есть контрольная линейка 50 мм.
- **Предметы и ёлка:** выбор любой из девяти ячеек для редактирования; каталог из 21 предмета/игрушки, своя подпись и символ, фото из галереи или камеры. Ячейки можно переставлять. Правильные ответы выбираются отдельно: три без порядка или четыре по порядку. Девять ячеек сохраняются как часть механики.
- **Два слоя снега:** две карточки, восемь накладок, просмотр отдельной накладки и совмещения, выбор ширины 144/168/184 мм и подлинной накладки. «Новый комплект» меняет seed и подлинную накладку; сохранённый seed воспроизводит прежнюю печать. PDF содержит три страницы A4: контрольное слово и карточки, затем восемь накладок. Используется актуальный алгоритм штрихов версии 3 из веб-версии.

Перед выгрузкой игра сохраняется. Готовый файл сначала создаётся в закрытом кэше, затем системный диалог предлагает выбрать папку, например «Загрузки». Отмена не создаёт файл назначения. Содержимое не зависит от последующих изменений черновика.

**16 ноября 2026 года код `8ee21d3` собран и установлен на S10e без очистки данных.** В сборку входят отдельные редакторы улик, печатный реквизит, экран правильного ответа, цветовые отметки прогресса, исправление удаления игры и объединённый экран настроек и запуска. Проверен запуск приложения; ручная проверка новых экранов и экспорта PDF остаётся за пользователем. NFC с настоящими метками отложен.

## Игровые механики

| Улика                       | Подготовка ведущим                                                                    | Действие игрока                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Метка на месте преступления | Метки с токенами, один подлинник; запись и проверка NDEF                              | Приложить телефон к метке. Настроенная ложная метка считается ошибкой; неизвестный токен не добавляет попытку |
| Разорванная фотография      | Снимок, токен, размер и кадрирование; предпросмотр и PDF для двусторонней печати      | Сканировать QR собранного пазла задней камерой                                                                |
| Три предмета в комнате      | Девять предметов из каталога или своих изображений, три правильные ячейки             | Выбрать три разных предмета, порядок не важен                                                                 |
| Фото до метели              | Снимок из галереи или камеры, подсказка, допустимые ответы                            | Ввести название исчезнувшего предмета                                                                         |
| След на ёлке                | Девять игрушек из каталога или своих изображений, четыре правильные ячейки по порядку | Нажать четыре разных символа в нужной последовательности                                                      |
| Два слоя снега              | Слово из 4–12 букв с чётной длиной; предпросмотр карточек/накладок и PDF              | Ввести слово без номера накладки                                                                              |
| Тихий обыск                 | Описание предмета, код метки, калибровка и чувствительность                           | Найти предмет, ввести четыре цифры при работающем шумомере; результат — число превышений                      |

В новой игре включены шесть исходных улик; «Тихий обыск» можно добавить отдельно. Можно оставить от одной до семи; повторное включение добавляет улику в конец. Номера задают позиции цифр замка. Играть можно в любом порядке, попытки не ограничены. Ввод фото и слова не зависит от регистра, лишних пробелов и различия «е/ё». Код — строка длиной по числу улик, поэтому начальные нули сохраняются. После правильного ответа показывается «Улика раскрыта!» с заработанной цифрой и её позицией. Игрок сам продолжает через «К уликам», а после последнего задания открывает финал кнопкой «Посмотреть результат»: полный код, общее время и самую долгую улику.

В блокноте команды пройденные улики выделены мягким зелёным фоном и галочкой. Статус «Улика раскрыта» и заработанная цифра остаются видны, а кнопка «Посмотреть улику» открывает сохранённый результат задания. Для непройденных улик остаётся нейтральное оформление. Карточку рисует `components/PlayerQuestCard.kt`, цвета заданы в `theme/Color.kt`.

Старые игры и прохождения с одним фото сохраняют свой состав. Их можно расширить в редакторе; для изменённого состава потребуется подготовить новое прохождение и код. Схема Room обновляется с версии 1 до 2 без очистки данных.

Сохраняются возможности второго этапа: пароль ведущего, несколько игр, переключение режимов без повторного входа, явный выход из сессии, инструктаж перед стартом таймера, история команд и сброс выбранного прохождения. Встроенного пароля нет: ведущий задаёт его при первом входе. После завершения процесса приложения нужен новый вход.

Дальше нужны ручная проверка на устройстве, пробная печать и прохождение несколькими командами. Полноценного редактора PDF нет: используются генераторы по шаблонам. Экспорт и импорт всей локальной базы пока отсутствуют.

После каждого этапа останавливаемся для разбора. Следующий этап начинается по отдельной команде пользователя.

## Как проверить новые механики

1. Откройте «Ведущий» и войдите со своим паролем. При первом запуске задайте пароль длиной от 8 до 128 символов.
2. Старый пример по-прежнему содержит только фото с ответом **«лампа»** или **«настольная лампа»**. Для остальных механик нажмите «Создать игру» или включите нужные улики в редакторе существующей.
3. В «Улики и сюжет» поменяйте порядок, потянув значок в правом углу карточки, затем нажмите «Настроить». Для своей ячейки выберите её в верхней сетке, затем предмет из каталога, свой символ или фото; правильные ответы отметьте в нижней сетке. Для фото доступны локальная галерея и штатная камера. На Samsung объектив переключается вручную.
4. В QR выберите размер и кадрирование, проверьте обе стороны и нажмите «Скачать PDF для печати». Для трафаретов проверьте карточки и накладки, затем скачайте PDF той же кнопкой. В системном диалоге выберите папку. Для NFC доступна «Записать метку» с последующей проверкой; нужны записываемые NDEF-метки.
5. В открытой игре перейдите в «Команда и запуск», задайте команду и код по числу улик, например `012345` для шести, затем нажмите «Передать команде». Настройки сохранятся автоматически. Для закрытия доступа к настройкам нажмите «Выйти».
6. Прочитайте историю и правила, начните расследование. Открывайте улики в любом порядке. Поворот и перезапуск приложения должны сохранять отметки времени и решённые задания.
7. Проверьте финальный код и историю попыток. В «Прохождениях команд» доступны повторное открытие и «Сбросить результаты»: очистятся ответы и время выбранного прохождения, команда и код сохранятся.

Пока NFC-меток нет, нажмите «Убрать» у этой улики. Для проверки QR нужен отдельный экран или бумага: телефон сканирует код камерой, чтение из собственной галереи не реализовано.

«К игре» из редактора сначала сохраняет изменения. При совпадении состава и порядка обновятся нерешённые задания активной незавершённой команды этой игры. При другой игре или другом составе откроется раздел «Команда и запуск» этой же игры; введённые команда и код сохранятся. Завершённые и другие команды сохраняют свои копии настроек.

Удаление игры также убирает с экрана команды связанное с ней активное прохождение. Команда увидит экран ожидания; прохождения другой игры продолжаются. Настройки, ответы и результаты удалённой игры сохраняются в истории. Ведущий может явно открыть архивное прохождение снова через «Открыть команде».

При первом запуске обновления также снимается старое активное прохождение, если его игра уже была удалена. Это разовое исправление данных, отмеченное в закрытых настройках приложения отдельно для каждой базы. Последующие запуски сохраняют явно открытые ведущим архивные прохождения. Схема Room не меняется.

«Сбросить результаты» перезапускает всё прохождение с последними сохранёнными настройками исходной игры; если она удалена — с копией из прохождения. Если число заданий изменилось и старый код больше не подходит, сброс покажет ошибку: нужно подготовить новое прохождение с подходящим кодом. «Сбросить улику» очищает только её прогресс и всегда сохраняет настройки из прохождения.

Пароль относится к этому телефону. Восстановление забытого пароля пока не реализовано. Удаление приложения или очистка его данных удалит игры и фотографии. Облачное резервное копирование отключено.

## Архитектура через аналогии с React

Порядок чтения:

1. **[MainActivity.kt](app/src/main/java/ru/pogman/questplatform/MainActivity.kt)** подключает Compose через `setContent` и получает ViewModel приложения. Это ближайший аналог точки загрузки React-приложения, но Activity управляется Android и может быть пересоздана при повороте.
2. **[QuestApp.kt](app/src/main/java/ru/pogman/questplatform/QuestApp.kt)** играет роль контейнера: подписывается на состояние, подключает UI и маршруты, обрабатывает события навигации и результат системного выбора фото.
3. **[viewmodel/OrganizerViewModel.kt](app/src/main/java/ru/pogman/questplatform/viewmodel/OrganizerViewModel.kt)** и **[PlayerViewModel.kt](app/src/main/java/ru/pogman/questplatform/viewmodel/PlayerViewModel.kt)** хранят состояние и выполняют действия. По ответственности это похоже на связку контейнера, store и async actions. Они переживают поворот экрана, но не завершение процесса.
4. **[data/QuestRepository.kt](app/src/main/java/ru/pogman/questplatform/data/QuestRepository.kt)** выполняет сценарии приложения: сохранить игру, подготовить команду, начать игру, принять ответ. Экраны не обращаются к SQLite напрямую.
5. **[data/QuestDao.kt](app/src/main/java/ru/pogman/questplatform/data/QuestDao.kt)** объявляет SQL-запросы. Room генерирует реализацию и уведомляет `Flow` о новых данных.
6. **[screens/GameScreen.kt](app/src/main/java/ru/pogman/questplatform/screens/GameScreen.kt)** объединяет настройки и запуск. `GameSettingsPanel` и `TeamSetupPanel` показывают разделы, а состояние формы поднято над их условным отображением, как `useState` в React над tabs. Старый маршрут `PrepareRun` перенаправляется сюда.
7. **[screens/QuestScreen.kt](app/src/main/java/ru/pogman/questplatform/screens/QuestScreen.kt)** выбирает интерфейс по типу улики: текст, сетку, NFC или QR. Принимает публичное состояние и callbacks; текст и выбранные ячейки держит локально.

| Android / Compose                     | Близкая идея из React                                                                    |
| ------------------------------------- | ---------------------------------------------------------------------------------------- |
| `@Composable` и recomposition         | Компонент и повторный render при изменении состояния                                     |
| `remember`                            | Локальное состояние между повторными вызовами компонента                                 |
| `rememberSaveable`                    | Локальное состояние с восстановлением при пересоздании окна; не долговременное хранилище |
| ViewModel + `StateFlow`               | Store со снимком состояния и потоком изменений                                           |
| `collectAsStateWithLifecycle`         | Подписка, активная пока UI видим; результат вызывает новый render                        |
| `DisposableEffect`                    | Эффект с синхронным освобождением ресурса, близко к `useEffect` с cleanup                |
| `LaunchedEffect`                      | Эффект с ключами и отменой при уходе из композиции                                       |
| `viewModelScope.launch`               | Асинхронное действие, отменяемое при окончательном уничтожении ViewModel                 |
| `rememberNavBackStack` + `NavDisplay` | Состояние роутера и отображение экрана по маршруту                                       |
| `MaterialTheme`                       | Глобальный контекст темы                                                                 |

Обычный путь действия: **callback экрана → ViewModel → repository → Room → Flow → состояние Compose → UI**. Одноразовые события начала игры и открытия улики меняют маршрут в `QuestApp`. Правильный ответ оставляет игрока на экране улики: по сохранённой награде `QuestScreen` показывает `QuestSuccessContent`, как условный render в React. На экране — подтверждение успеха, цифра, её позиция и время; клавиатура и сканеры закрываются. «К уликам» возвращает в блокнот, а после последней улики «Посмотреть результат» открывает финал. Время решения и завершения фиксируется при ответе, а не при нажатии этой кнопки. Состояние успеха сохраняется при повороте и повторном открытии решённого задания.

`Game.quests` — список заданий. `QuestConfig` — sealed interface, аналог union-типа TypeScript; конкретные `PhotoQuestConfig`, `NfcQuestConfig` и остальные задают допустимые поля. `when` выбирает нужную ветку, а компилятор требует обработать все варианты. `QuestEditor` связывает общую форму с небольшими редакторами каждой механики. `QuestAnswer` также разделяет текст, токен и список выбранных ячеек. Чистая функция `evaluateAnswer` не зависит от Android.

`NfcReader` включает системный ReaderMode только для активного экрана и возобновлённого окна. `QrScanner` связывает CameraX с lifecycle и освобождает камеру и ML Kit при уходе с маршрута. В React это похоже на подписку в `useEffect` с cleanup, но здесь нужно учитывать ещё фон приложения и анимированный уход экрана. Чтение и запись меток выполняет `NfcTagStore` вне UI-потока.

Парольные поля используют `remember`, чтобы пароль не попадал в сохранённое состояние Android. Черновик игры находится в ViewModel и переживает поворот; он записывается в Room по «Сохранить игру», «К игре» или «Передать команде». После обычного сохранения черновик и форма команды остаются на экране. Поля передают функцию изменения актуального черновика, аналог `setState(prev => ...)` в React: старый обработчик ввода не заменяет асинхронно загруженное фото устаревшей копией игры. Сессия ведущего хранится в памяти до «Выйти» или завершения процесса, а переключение режимов её не закрывает. Защита проверяется и при показе приватных экранов, и перед операциями с данными.

`Column`, `Row`, `Box` описывают раскладку; `Modifier` — размер и отступы. `dp` — единицы размера интерфейса, `sp` — текста с учётом системного масштаба. `ScreenContent` добавляет прокрутку и ограничение ширины; общая оболочка учитывает экранную клавиатуру.

## Как устроены генераторы

`domain/StencilGlyphs.kt` и `domain/StencilKit.kt` содержат геометрию букв и детерминированное разбиение на штрихи: это порт текущей версии `src/client/utils/stencilStrokes.ts`. Сохранённые `strokeSeed` и `strokeVersion` нельзя менять автоматически при повторной печати. Новые настройки записываются явно через `encodeDefaults`; прежние JSON без этих полей читаются со стабильными значениями по умолчанию.

`domain/PrintLayout.kt` строит страницы как список текста, линий, прямоугольников и изображения в миллиметрах. Это аналог чистой функции в React, которая превращает props в дерево представления. `components/PrintPreview.kt` и `data/MaterialStore.kt` используют один `data/PrintCanvas.kt`, поэтому размеры и расположение элементов не вычисляются повторно разными способами. Растровый снимок учитывает EXIF-поворот; QR и штрихи остаются векторными в PDF.

`MaterialActions.kt` похож на custom hook: подключает системный диалог сохранения PDF и возвращает результат ViewModel. [Android PdfDocument](https://developer.android.com/reference/android/graphics/pdf/PdfDocument) создаёт PDF, а [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files#create-file) предоставляет доступ только к выбранному пользователем файлу. Новых разрешений для экспорта не добавлено.

## Как хранятся данные

Room — библиотека над **SQLite, встроенной в Android**. Это локальный файл `quest-platform.db` в закрытой папке приложения. Отдельного сервиса базы данных нет. Таблицы нужны для игр, прохождений и журнала; транзакция сохраняет ответ, награду и завершение игры согласованно. Настройки каждого задания записываются JSON внутри строки таблицы; тип хранится в `questId`, порядок — в `position`. `QuestConfigs` выбирает конкретный сериализатор и читает прежний JSON фото без изменения формата.

Прохождение содержит копии названия, истории, правил, заданий и цифр. Сохранение игры обновляет только активную незавершённую команду при совпадении типов и порядка улик; решённые задания и другие команды сохраняют прежние настройки. Модель `PlayerRun` не содержит правильных ответов, NFC/QR-токенов и невыданных цифр. Общий код появляется только после решения всех улик. Пароль хранится как PBKDF2-HMAC-SHA256 хеш с индивидуальной случайной солью и 600 000 итераций.

Выбор из галереи возвращает URI, а `PhotoStore` копирует файл внутрь приложения. Поэтому старое прохождение не зависит от доступа к исходнику в галерее. Импорт принимает изображения до 25 МБ и 100 мегапикселей. Для импорта не требуется общий доступ ко всей галерее. Иллюстрация примера — векторный ресурс в репозитории.

На Android без Photo Picker вместо перехода в список документов используется запрос локальной картинки из галереи (`ACTION_PICK`); также передаётся `EXTRA_LOCAL_ONLY`. На S10e этот запрос обрабатывают Samsung Gallery и Google Фото. Облачное хранилище документов не открывается как запасной вариант.

`rememberPhotoActions` похож на custom hook: регистрирует обработчики системных результатов и возвращает callbacks для кнопок. Съёмка фотографии использует штатное приложение камеры и временный `content://` URI через `FileProvider`, которому открыт только каталог `cache/camera/`. После импорта или отмены временный файл удаляется. URI ожидающего снимка сохраняется при пересоздании Activity, а результат привязан к игре и типу улики.

Для QR добавлено разрешение `CAMERA`. Теперь его нужно получить и перед внешней съёмкой фото: Android проверяет разрешение у приложения, которое объявило его в манифесте. Фото остаётся в штатной Samsung Camera; выбор объектива там ручной, как согласовано с пользователем. Неэффективные подсказки о заднем объективе удалены. Отдельный экран CameraX использует заднюю камеру только для QR, не для фотографирования.

QR читается через [CameraX и MlKitAnalyzer](https://developer.android.com/reference/androidx/camera/mlkit/vision/MlKitAnalyzer). Выбран [bundled-вариант ML Kit](https://developers.google.com/ml-kit/vision/barcode-scanning/android): модель включается в APK, загрузка перед первым сканированием не нужна. ZXing строит QR в редакторе. Повтор одного кода в непрерывном видеопотоке не создаёт множество попыток: для повторной проверки есть «Сканировать ещё раз».

NFC использует Android `NfcAdapter` и NDEF, не Web NFC. Записывается текстовый токен; чтение понимает UTF-8/UTF-16 text records и URI. Проверяются доступность NFC, включённое состояние, возможность записи и вместимость метки. Аппаратные возможности объявлены необязательными: приложение можно открыть на устройстве без NFC или камеры, а нужный экран объяснит ограничение.

Сброс всего прохождения выполняется одной транзакцией. Старое прохождение заменяется чистым с новым ID и текущими сохранёнными настройками игры. Если исходная игра удалена, используется прежняя копия. При изменении числа улик старый код не переносится: операция завершается ошибкой до удаления данных. Это также меняет ключ локального состояния UI, как новый `key` в React: прежний введённый ответ не переносится в повторный тест. Старые попытки удаляются по связям Room; данные других команд не затрагиваются.

Сброс одной улики тоже транзакционный, но сохраняет ID команды и копию её настроек. `run_quests.revision` увеличивается при сбросе: этот номер входит в ключ Compose-экрана и проверяется при отправке ответа. Аналогия с React — новый `key` очищает локальный ввод и выбор ячеек. Запоздалый ответ, чтение NFC или старая сессия микрофона не могут восстановить сброшенный прогресс. Для этого Room обновлён до версии 3 миграцией `MIGRATION_2_3`, добавляющей только `revision` с начальным значением 0. Переход с версии 1 проходит через обе миграции 1→2→3, без очистки данных.

Таймеры считаются по сохранённым отметкам начала и окончания. Повторный старт и повторное открытие не сбрасывают их. Тик UI только обновляет отображение. Используется системное время телефона: ручной перевод часов влияет на длительность.

| `build.gradle.kts`, `app/build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, `gradle/libs.versions.toml` | Наши настройки сборки и зависимостей                                                                       |
| `gradlew`, `gradlew.bat`, `gradle/wrapper/`                                                                         | Созданы командой `gradle wrapper`; сохраняются в Git                                                       |
| `app/schemas/…/{1,2,3}.json`                                                                                        | Room генерирует описание схемы из наших `@Entity`; сохраняем в Git для будущих миграций, вручную не правим |
| `app/build/generated/ksp/`                                                                                          | KSP/Room генерируют реализацию DAO и базы из наших объявлений; исключено из Git                            |
| `app/build/`, `build/`                                                                                              | APK, классы, ресурсы `R`, сериализаторы `@Serializable`, отчёты; не редактируем и не коммитим              |
| `.gradle/`, `.kotlin/`, `local.properties`                                                                          | Кэши и локальный путь к SDK; исключены из Git                                                              |

Версии библиотек собраны в `gradle/libs.versions.toml`, аналогично централизованному списку версий npm-пакетов. AndroidX, Compose, Room, Coil, CameraX, ML Kit и ZXing — внешние библиотеки. Их код не написан нами. В `AppContainer` зависимости связаны вручную: отдельного DI-фреймворка на этом этапе нет.
