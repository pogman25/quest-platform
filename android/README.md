# Android-приложение «Бюро квестов»

Нативное приложение на Kotlin и Jetpack Compose. Ведущий настраивает игру и передаёт тот же телефон команде. Сервер, веб-админка, Node.js и Docker для Android-версии не нужны.

## Этап 2: первая игра целиком

Реализован полный сценарий одного задания **«Фото до метели»**:

- Первый запуск: ведущий задаёт собственный пароль, встроенного пароля нет. Доступны вход, выход и смена пароля с проверкой текущего.
- Несколько игр: создание, редактирование и удаление; название, история, правила, снимок, подсказка и допустимые ответы.
- Два источника снимка: **«Из галереи»** для локальных изображений и **«Снять фото»** через приложение камеры. Выбранный снимок копируется в закрытую папку приложения. Для пробы есть иллюстрация комнаты; допустимый ответ в готовом примере — **«лампа»** или **«настольная лампа»**.
- Подготовка прохождения: название команды и одна цифра кода от 0 до 9. Кнопка «Передать команде» закрывает доступ ведущего.
- Инструктаж и явная кнопка начала: чтение истории не запускает таймер.
- Задание: снимок, текстовый ответ, неограниченные повторы. При сравнении игнорируются регистр, лишние пробелы и различие «е/ё».
- Финал: заработанная цифра, общее время и время самой долгой улики. На этом этапе улика одна, поэтому код состоит из одной цифры.
- История команд: состояние, времена, число попыток, журнал ответов и повторное открытие выбранного прохождения. **«Сбросить результаты»** с подтверждением очищает ответы, награду и время выбранной команды и открывает инструктаж заново; команда и копия настроек сохраняются.
- Сохранение игр, фотографий, прогресса и результатов на телефоне, включая перезапуск приложения.

Остальные пять механик, NFC, QR, генерация печатных материалов и выгрузка текстов относятся к следующим этапам. Полноценный редактор PDF не планируется: нужны генераторы по шаблонам, аналогичные веб-версии. Экспорт и импорт локальных данных пока отсутствуют.

После каждого этапа разработка останавливается для разбора. Следующий этап начинается по отдельной команде пользователя.

## Как проверить игру вручную

1. Откройте «Ведущий», задайте и подтвердите пароль длиной от 8 до 128 символов.
2. Откройте «Настроить» у готовой игры. Для реальной игры выберите «Из галереи» или «Снять фото», задайте названия предмета и уберите его перед началом. Если Android предложит несколько приложений, выберите «Галерея». Для пробы можно оставить иллюстрацию и ответ «лампа».
3. Сохраните игру, нажмите «Подготовить игру», задайте название команды и цифру, затем «Передать команде».
4. Прочитайте историю и правила. Нажмите «Начать расследование», откройте улику, попробуйте неверный и правильный ответы.
5. Во время задания поверните телефон или закройте приложение и откройте снова: прогресс и начало отсчёта сохранятся.
6. В финале проверьте цифру и время. Вернитесь к блокноту, войдите как ведущий и откройте «Прохождения команд» → «Показать ответы».
7. Для следующей команды подготовьте новое прохождение. Изменения исходной игры применяются к новым прохождениям; уже подготовленные используют прежние настройки.
8. Для повторного теста той же команды: «Ведущий» → «Прохождения команд» → «Сбросить результаты» → подтвердите сброс. Остальные команды и пароль не меняются. Таймер снова начнётся только после «Начать расследование».

Пароль относится к этому телефону. Восстановление забытого пароля пока не реализовано. Данные лежат в папке приложения; удаление приложения или очистка его данных удалит и игры. Облачное резервное копирование отключено.

## Запуск в Android Studio

1. Откройте папку `quest-platform/android`, дождитесь Gradle Sync. В настройках Gradle JDK выберите **Embedded JDK** Android Studio.
2. Через **Tools → SDK Manager** установите платформу API 37.0, Build-Tools 36.0.0 и Platform-Tools.
3. На Samsung включите отладку по USB и подтвердите разрешение компьютеру. Параметры разработчика открываются после семи нажатий на **Настройки → Сведения о телефоне → Сведения о ПО → Номер сборки**.
4. Выберите устройство и нажмите **Run ▶**.

Проверяем на Samsung Galaxy S10e / Android 12 / API 31. `minSdk = 26` задаёт минимальную версию Android. `compileSdk = 37` задаёт доступные при компиляции API, `targetSdk = 37` — правила поведения приложения. Обновлять телефон до этой версии не требуется.

## Сборка в терминале

Gradle Wrapper фиксирует версию сборщика; глобальная установка Gradle не нужна. При первой сборке требуется интернет для загрузки инструментов и библиотек.

На этом Mac Android Studio установлен в пользовательской папке Applications:

```sh
cd /Users/alexpogorelov/Documents/own/quest-platform/android
export JAVA_HOME="/Users/alexpogorelov/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew assembleDebug testDebugUnitTest lintDebug assembleDebugAndroidTest
```

Если Android Studio установлен для всех пользователей, путь к JDK начинается с `/Applications/Android Studio.app/`. Android Studio создаёт `local.properties` с локальным путём к SDK; этот файл исключён из Git.

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`. Установка на единственный подключённый USB-телефон с сохранением данных:

```sh
"$ANDROID_HOME/platform-tools/adb" -d install -r app/build/outputs/apk/debug/app-debug.apk
"$ANDROID_HOME/platform-tools/adb" -d shell am start -W \
    -a android.intent.action.MAIN \
    -c android.intent.category.LAUNCHER \
    -n ru.pogman.questplatform/.MainActivity
```

Запускайте через MAIN/LAUNCHER, как иконку приложения. `MainActivity` использует `launchMode="singleTop"`: повторное открытие поверх текущего окна переиспользует его. На Android 12 системная кнопка «Назад» со стартового экрана переводит приложение в фон; из вложенного экрана возвращает назад. Выход с главного экрана ведущего закрывает его сессию.

## Где лежит код

`app/src/main` — стандартное расположение исходников Android. В каталоге `java` находится наш Kotlin-код. Путь `ru/pogman/questplatform` соответствует имени пакета; считайте его аналогом фронтендового `src`. Внутри каталоги плоские, по назначению:

```text
app/
├── src/main/
│   ├── AndroidManifest.xml       # Application, Activity, системные настройки
│   ├── java/ru/pogman/questplatform/
│   │   ├── MainActivity.kt       # Точка входа окна
│   │   ├── QuestApplication.kt   # Объект приложения на время процесса
│   │   ├── AppContainer.kt       # Создание и связывание зависимостей
│   │   ├── QuestApp.kt           # Контейнер UI: состояние, события, навигация
│   │   ├── PhotoActions.kt       # Подключение системных результатов, аналог custom hook
│   │   ├── PhotoContracts.kt     # Запросы выбора локального фото и съёмки
│   │   ├── screens/              # Экраны: данные и callbacks через параметры
│   │   ├── components/           # Общая оболочка и части интерфейса
│   │   ├── navigation/           # Маршруты и защита содержимого ведущего
│   │   ├── viewmodel/            # Состояние и действия игрока/ведущего
│   │   ├── domain/               # Модели и чистые правила без Android API
│   │   ├── data/                 # Room, репозиторий, пароль, файлы фотографий
│   │   └── theme/                # Цвета, типографика, тема Material 3
│   └── res/                      # Русские строки, изображения, тема окна
├── src/test/                     # JVM-тесты без устройства
├── src/androidTest/              # Наши тесты с настоящим Android и SQLite
└── schemas/                      # Сгенерированные Room описания схемы
```

## Архитектура через аналогии с React

Порядок чтения:

1. **[MainActivity.kt](app/src/main/java/ru/pogman/questplatform/MainActivity.kt)** подключает Compose через `setContent` и получает две ViewModel. Это ближайший аналог точки загрузки React-приложения, но Activity управляется Android и может быть пересоздана при повороте.
2. **[QuestApp.kt](app/src/main/java/ru/pogman/questplatform/QuestApp.kt)** играет роль контейнера: подписывается на состояние, подключает UI и маршруты, обрабатывает события навигации и результат системного выбора фото.
3. **[viewmodel/OrganizerViewModel.kt](app/src/main/java/ru/pogman/questplatform/viewmodel/OrganizerViewModel.kt)** и **[PlayerViewModel.kt](app/src/main/java/ru/pogman/questplatform/viewmodel/PlayerViewModel.kt)** хранят состояние и выполняют действия. По ответственности это похоже на связку контейнера, store и async actions. Они переживают поворот экрана, но не завершение процесса.
4. **[data/QuestRepository.kt](app/src/main/java/ru/pogman/questplatform/data/QuestRepository.kt)** выполняет сценарии приложения: сохранить игру, подготовить команду, начать игру, принять ответ. Экраны не обращаются к SQLite напрямую.
5. **[data/QuestDao.kt](app/src/main/java/ru/pogman/questplatform/data/QuestDao.kt)** объявляет SQL-запросы. Room генерирует реализацию и уведомляет `Flow` о новых данных.
6. **[screens/PhotoQuestScreen.kt](app/src/main/java/ru/pogman/questplatform/screens/PhotoQuestScreen.kt)** показывает обычный UI: принимает состояние и callbacks, держит введённый ответ локально.

| Android / Compose                     | Близкая идея из React                                                                    |
| ------------------------------------- | ---------------------------------------------------------------------------------------- |
| `@Composable` и recomposition         | Компонент и повторный render при изменении состояния                                     |
| `remember`                            | Локальное состояние между повторными вызовами компонента                                 |
| `rememberSaveable`                    | Локальное состояние с восстановлением при пересоздании окна; не долговременное хранилище |
| ViewModel + `StateFlow`               | Store со снимком состояния и потоком изменений                                           |
| `collectAsStateWithLifecycle`         | Подписка, активная пока UI видим; результат вызывает новый render                        |
| `LaunchedEffect`                      | Эффект с ключами и отменой при уходе из композиции                                       |
| `viewModelScope.launch`               | Асинхронное действие, отменяемое при окончательном уничтожении ViewModel                 |
| `rememberNavBackStack` + `NavDisplay` | Состояние роутера и отображение экрана по маршруту                                       |
| `MaterialTheme`                       | Глобальный контекст темы                                                                 |

Обычный путь действия: **callback экрана → ViewModel → repository → Room → Flow → состояние Compose → UI**. Одноразовое событие, например успешное решение, отдельно меняет маршрут в `QuestApp`.

Парольные поля используют `remember`, чтобы пароль не попадал в сохранённое состояние Android. Черновик игры находится в ViewModel и переживает поворот; он записывается в Room только после сохранения. Сессия ведущего хранится в памяти и закрывается при выходе к игроку, передаче команде или завершении процесса. Защита проверяется и при показе приватных экранов, и перед операциями с данными.

`Column`, `Row`, `Box` описывают раскладку; `Modifier` — размер и отступы. `dp` — единицы размера интерфейса, `sp` — текста с учётом системного масштаба. `ScreenContent` добавляет прокрутку и ограничение ширины; общая оболочка учитывает экранную клавиатуру.

## Как хранятся данные

Room — библиотека над **SQLite, встроенной в Android**. Это локальный файл `quest-platform.db` в закрытой папке приложения. Отдельного сервиса базы данных нет. Таблицы нужны для игр, прохождений и журнала; транзакция сохраняет ответ, награду и завершение игры согласованно. Настройки фото-задания записываются JSON внутри строки таблицы.

Прохождение содержит копию названия, истории, правил, задания и цифры. Правильные ответы и невыданная цифра не входят в модель `PlayerRun`, которую получает UI игрока. Пароль хранится как PBKDF2-HMAC-SHA256 хеш с индивидуальной случайной солью и 600 000 итераций; открытого пароля в Room нет.

Выбор из галереи возвращает URI, а `PhotoStore` копирует файл внутрь приложения. Поэтому старое прохождение не зависит от доступа к исходнику в галерее. Импорт принимает изображения до 25 МБ и 100 мегапикселей. Интернет и общий доступ к галерее приложению не требуются. Иллюстрация примера — векторный ресурс в репозитории.

На Android без Photo Picker вместо перехода в список документов используется запрос локальной картинки из галереи (`ACTION_PICK`); также передаётся `EXTRA_LOCAL_ONLY`. На S10e этот запрос обрабатывают Samsung Gallery и Google Фото. Облачное хранилище документов не открывается как запасной вариант.

`rememberPhotoActions` похож на custom hook: регистрирует обработчики результатов и возвращает callbacks для кнопок. Съёмка использует системное приложение камеры и временный `content://` URI через `FileProvider`, которому открыт только каталог `cache/camera/`. После импорта или отмены временный файл удаляется. Прямой доступ нашего приложения к камере и разрешение `CAMERA` не требуются. URI ожидающего снимка сохраняется при пересоздании Activity, а результат привязан к конкретной редактируемой игре.

Сброс результатов выполняется одной транзакцией. Старое прохождение заменяется чистым с новым ID и прежней копией настроек — даже если исходная игра удалена. Это также меняет ключ локального состояния UI, как новый `key` в React: прежний введённый ответ не переносится в повторный тест. Старые попытки удаляются по связям Room; данные других команд не затрагиваются.

Таймеры считаются по сохранённым отметкам начала и окончания. Повторный старт и повторное открытие не сбрасывают их. Тик UI только обновляет отображение. Используется системное время телефона: ручной перевод часов влияет на длительность.

## Что написано нами, что генерируется

Проект создан без мастера Android Studio. Стандартное расположение папок не означает, что их содержимое автоматически сгенерировано.

| Часть проекта                                                                                                       | Происхождение                                                                                              |
| ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `app/src/main/`, `app/src/test/`, `app/src/androidTest/`                                                            | Наш код, ресурсы, SQL-запросы и тесты; здесь идёт основная разработка                                      |
| `build.gradle.kts`, `app/build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, `gradle/libs.versions.toml` | Наши настройки сборки и зависимостей                                                                       |
| `gradlew`, `gradlew.bat`, `gradle/wrapper/`                                                                         | Созданы командой `gradle wrapper`; сохраняются в Git                                                       |
| `app/schemas/…/1.json`                                                                                              | Room генерирует описание схемы из наших `@Entity`; сохраняем в Git для будущих миграций, вручную не правим |
| `app/build/generated/ksp/`                                                                                          | KSP/Room генерируют реализацию DAO и базы из наших объявлений; исключено из Git                            |
| `app/build/`, `build/`                                                                                              | APK, классы, ресурсы `R`, сериализаторы `@Serializable`, отчёты; не редактируем и не коммитим              |
| `.gradle/`, `.kotlin/`, `local.properties`                                                                          | Кэши и локальный путь к SDK; исключены из Git                                                              |

Версии библиотек собраны в `gradle/libs.versions.toml`, аналогично централизованному списку версий npm-пакетов. AndroidX, Compose, Room и Coil — внешние библиотеки. Их код не написан нами. В `AppContainer` зависимости связаны вручную: отдельного DI-фреймворка на этом этапе нет.

## Автоматические проверки

После дополнения второго этапа прошли сборка APK, Android Lint без ошибок, три JVM-теста и все 13 Android-тестов как на эмуляторе API 31, так и на Samsung Galaxy S10e с Android 12. Предупреждения Lint относятся к доступным обновлениям зависимостей.

JVM-тесты проверяют нормализацию ответов, расчёт времени и работу хеша. Android-тесты проверяют настоящую SQLite: неизменность копии настроек, сохранение после повторного открытия базы, попытки, фото, пароль и отсутствие сохранённой сессии. UI-тесты проходят путь от первого пароля до результата и проверяют навигацию и пересоздание Activity.

Дополнительные тесты проверяют перезапуск выбранной команды без исходной игры, сохранность других команд, отмену подтверждения и повторное решение с пустым полем ответа. Для фото Activity Result Registry возвращает контролируемые результаты галереи и камеры через настоящий FileProvider: проверяются локальный запрос, импорт, очистка временного файла, отмена и запоздалый результат для другой игры. В этих тестах камера не снимает окружение пользователя.

UI-тесты заменяют контейнер до запуска Activity и используют отдельную базу. Для запуска используйте тестовый эмулятор Android 12; Gradle `connectedAndroidTest` может переустанавливать приложение, поэтому его не следует запускать на телефоне с рабочими данными. Прямой запуск на эмуляторе после сборки:

```sh
"$ANDROID_HOME/platform-tools/adb" -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
"$ANDROID_HOME/platform-tools/adb" -s emulator-5554 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
"$ANDROID_HOME/platform-tools/adb" -s emulator-5554 shell am instrument -w \
    ru.pogman.questplatform.test/androidx.test.runner.AndroidJUnitRunner
```

Отдельный тест сохраняет исправление первого этапа: повторный запуск не создаёт одинаковые Activity и для выхода достаточно одного системного «Назад».
