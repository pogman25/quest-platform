# Android-приложение «Бюро квестов»

Это нативное приложение на Kotlin и Jetpack Compose. Оно собирается отдельно от веб-приложения в корне репозитория. Для запуска Android-версии не нужны Node.js, Docker и сервер.

## Этап 1: первый запуск

Реализована оболочка приложения:

- Светлая тема в стиле «Блокнот команды», русские строки и иконка приложения.
- Стартовый экран игрока в состоянии «Дело ещё не открыто».
- Экран общих правил и экран входа ведущего.
- Навигация через Navigation 3 с системным возвратом и восстановлением маршрута после пересоздания Activity.
- Compose Preview для стартового экрана.

Кнопка задания пароля намеренно отключена. Вход, хранение данных, редактор и игровые механики относятся к следующим этапам. В приложении нет демонстрационного обхода пароля и фиктивного прохождения.

После каждого этапа разработка останавливается для разбора. Следующий этап начинается только по явной команде пользователя.

## Запуск в Android Studio

1. Установите Android Studio для вашего Mac. На Apple Silicon нужна сборка **Mac with Apple chip**.
2. Откройте именно папку `quest-platform/android`, дождитесь Gradle Sync. В настройках Gradle JDK выберите **Embedded JDK** Android Studio.
3. Через **Tools → SDK Manager** установите платформу Android 17 / API 37.0, SDK Build-Tools 36.0.0 и Android SDK Platform-Tools.
4. Для телефона включите отладку по USB, подключите кабель с передачей данных и подтвердите разрешение на отладку на экране телефона.
5. Выберите телефон в списке устройств и нажмите **Run ▶**. Для первой установки магазина приложений не требуется.

Целевой телефон — Samsung Galaxy S10e с Android 12 / API 31. `minSdk = 26` задаёт минимальную поддерживаемую версию Android, `compileSdk = 37` — набор API для компиляции. Эти значения не требуют обновлять телефон до Android 17. `targetSdk = 37` включает современные правила поведения Android.

### Включение отладки на Samsung

**Настройки → Сведения о телефоне → Сведения о ПО → Номер сборки**: нажмите семь раз. Затем откройте **Настройки → Параметры разработчика → Отладка по USB**.

Если телефон не отображается, проверьте кабель, режим USB и диалог разрешения на телефоне. Команда `adb devices -l` показывает доступные устройства; состояние `unauthorized` означает, что подтверждение на телефоне ещё не получено.

## Сборка в терминале

Gradle Wrapper фиксирует версию Gradle в проекте, поэтому устанавливать глобальный Gradle не требуется. При первой сборке нужен интернет для загрузки инструментов и библиотек.

На этом Mac Android Studio установлен в пользовательскую папку Applications:

```sh
cd /Users/alexpogorelov/Documents/own/quest-platform/android
export JAVA_HOME="/Users/alexpogorelov/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew assembleDebug lintDebug
```

Если Android Studio установлен для всех пользователей, путь к JDK будет `/Applications/Android Studio.app/Contents/jbr/Contents/Home`.

Путь к SDK записан в локальном `local.properties`: его может создать Android Studio или разработчик при настройке окружения. Этот файл, кэши и результаты сборки исключены из Git. Сам SDK устанавливается отдельно от репозитория.

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`.

```sh
"$ANDROID_HOME/platform-tools/adb" devices -l
./gradlew installDebug
```

Для запуска через ADB используйте тот же тип Intent, что и иконка приложения:

```sh
"$ANDROID_HOME/platform-tools/adb" shell am start -W \
    -a android.intent.action.MAIN \
    -c android.intent.category.LAUNCHER \
    -n ru.pogman.questplatform/.MainActivity
```

`MainActivity` использует `launchMode="singleTop"`: повторное открытие поверх текущего окна переиспользует его. Это предотвращает появление одинаковых Activity друг над другом, из-за которых первое нажатие «Назад» выглядело как мигание. На Android 12 системная кнопка «Назад» со стартового экрана переводит приложение в фон.

## Как читать код фронтенд-разработчику

Начните с четырёх мест:

1. **[MainActivity.kt](app/src/main/java/ru/pogman/questplatform/MainActivity.kt)** — Android-точка входа, ближайший аналог загрузки React-приложения. Activity получает события жизненного цикла и подключает Compose через `setContent`.
2. **[QuestApp.kt](app/src/main/java/ru/pogman/questplatform/QuestApp.kt)** — тема, общая оболочка и маршрутизация. `rememberNavBackStack` хранит стек экранов; `NavDisplay` отображает текущий экран. Маршруты объявлены в [navigation/QuestRoute.kt](app/src/main/java/ru/pogman/questplatform/navigation/QuestRoute.kt).
3. **[screens/PlayerHomeScreen.kt](app/src/main/java/ru/pogman/questplatform/screens/PlayerHomeScreen.kt)** — UI-компонент. `@Composable`-функция описывает интерфейс; callback `onInstructions` передаётся сверху, как обработчик в React.
4. **[theme/](app/src/main/java/ru/pogman/questplatform/theme)** — цвета, типографика и формы Material 3. `MaterialTheme` предоставляет их вложенным компонентам, примерно как глобальный React Context.

```text
app/src/main/
├── AndroidManifest.xml        # Компоненты приложения и системные настройки
├── java/ru/pogman/questplatform/
│   ├── MainActivity.kt
│   ├── QuestApp.kt            # Общая оболочка и подключение навигации
│   ├── navigation/
│   │   └── QuestRoute.kt      # Типы маршрутов
│   ├── screens/               # Экраны приложения
│   │   ├── PlayerHomeScreen.kt
│   │   ├── InstructionsScreen.kt
│   │   └── OrganizerEntryScreen.kt
│   ├── components/            # UI-компоненты и части экранов
│   │   ├── QuestTopBar.kt
│   │   ├── ScreenContent.kt
│   │   ├── NotebookEmblem.kt
│   │   ├── CaseIntroduction.kt
│   │   └── InstructionStep.kt
│   └── theme/
│       ├── QuestTheme.kt
│       ├── Color.kt
│       └── Type.kt
└── res/
    ├── values/strings.xml     # Русские строки
    ├── values/themes.xml      # Тема окна до первого кадра Compose
    └── drawable/              # Ресурсы изображений
```

`app/src/main` — стандартное расположение основных исходников Android. Каталог `java` содержит наш Kotlin-код, а `ru/pogman/questplatform` соответствует базовому пакету приложения. Для чтения кода эту папку удобно считать аналогом фронтендового `src`. Внутри неё используются четыре плоских каталога по назначению; каждый компонент занимает отдельный файл.

`Column`, `Row` и `Box` задают расположение элементов; `Modifier` описывает размер, отступы и другие свойства. `dp` — единицы размера интерфейса, `sp` — размер текста с учётом системного масштаба шрифта. `stringResource` читает текст из ресурсов.

Compose вызывает функции UI повторно при изменении наблюдаемого состояния. Это называется **recomposition** и близко к повторному рендеру React. Не запускайте запись файлов, запросы и другую инфраструктуру непосредственно из тела UI-функции. На втором этапе подключим ViewModel и Room; сейчас экраны не требуют этого слоя.

`ScreenContent` — общая оболочка, которая добавляет вертикальную прокрутку, отступы и ограничение ширины. Она нужна, чтобы длинный текст и крупный системный шрифт не обрезали кнопки.

Версии зависимостей находятся в `gradle/libs.versions.toml` — это аналог централизованного списка версий пакетов. `app/build.gradle.kts` описывает сборку Android-модуля. С AGP 9 Kotlin уже встроен; комментарий в корневом Gradle-файле объясняет выравнивание его версии с Compose Compiler.

## Что редактируем и что генерируется

Проект создан без мастера Android Studio. Стандартные каталоги содержат наши редактируемые исходники и настройки.

| Часть проекта                                                                                                       | Происхождение и назначение                                                                                              |
| ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `app/src/main/java/`, `app/src/main/res/`, `app/src/main/AndroidManifest.xml`                                       | Написанные нами код, ресурсы и настройки приложения. Здесь выполняется основная разработка.                             |
| `app/src/androidTest/`                                                                                              | Написанные нами UI-тесты для телефона или эмулятора.                                                                    |
| `build.gradle.kts`, `app/build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, `gradle/libs.versions.toml` | Наши настройки сборки и зависимостей.                                                                                   |
| `gradlew`, `gradlew.bat`, `gradle/wrapper/`                                                                         | Созданы командой `gradle wrapper` с выбранными нами версией и контрольной суммой Gradle. Хранятся вместе с исходниками. |
| `app/build/`, `build/`                                                                                              | Результаты сборки: APK, классы, сгенерированные ресурсы и отчёты. Вручную не редактируются и в Git не сохраняются.      |
| `.gradle/`, `.kotlin/`                                                                                              | Служебные кэши инструментов; исключены из Git.                                                                          |
| `local.properties`                                                                                                  | Локальный путь к Android SDK; задаётся для конкретного компьютера и исключён из Git.                                    |

Классы ресурсов `R` и сериализаторы для маршрутов с `@Serializable` создаются компилятором из наших ресурсов и Kotlin-объявлений. `ComponentActivity`, `Scaffold` и `NavDisplay` приходят из подключённых библиотек AndroidX.

## Самостоятельная проверка этапа

При завершении первого этапа сборка и Android Lint прошли. На Samsung Galaxy S10e (SM-G970F), Android 12, прошли оба UI-теста: восстановление маршрута после пересоздания Activity и возврат с экрана ведущего. Итоговый APK был отдельно установлен на телефон после завершения тестов.

Отдельный регрессионный тест проверяет повторное открытие `MainActivity` и выход со стартового экрана по одному нажатию «Назад».

После упрощения структуры прошли чистая сборка APK, Android Lint и компиляция UI-тестов. Для повторной проверки:

```sh
./gradlew clean assembleDebug lintDebug assembleDebugAndroidTest
```

1. Откройте приложение: виден «Блокнот команды» и состояние ожидания игры.
2. Нажмите «Как играть», прочитайте правила, вернитесь кнопкой «Всё понятно».
3. Откройте «Ведущий»: виден экран первого запуска, кнопка «Задать пароль» отключена.
4. Вернитесь системной кнопкой/жестом Back; откройте правила и поверните телефон — маршрут должен сохраниться.
5. Увеличьте системный размер шрифта и проверьте прокрутку. Приложение остаётся светлым при включённой тёмной теме телефона.

Автоматические проверки навигации запускаются на подключённом телефоне или эмуляторе:

```sh
./gradlew connectedDebugAndroidTest
```

Тестовый запуск может удалить APK после завершения. Чтобы оставить приложение на телефоне, выполните `./gradlew installDebug` после тестов. В тестах используется Compose Test API v2; `waitForIdle()` перед первым действием дожидается начальной композиции.
