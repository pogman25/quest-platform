# Бюро квестов

Админка на React и TypeScript, API на Express, база PostgreSQL. Express обслуживает API и веб-сборку с одного адреса.

## Запуск в Docker

Скопируйте `.env.example` в `.env`. Задайте `POSTGRES_PASSWORD` и пароль организатора `ADMIN_PASSWORD`. Для локального примера можно использовать почту `organizer@example.test` и пароль `demo-password`.

```sh
docker compose up --build -d --wait
docker compose exec app npm run db:seed
```

Админка открывается на [127.0.0.1:4173](http://127.0.0.1:4173). Docker Compose ждёт готовности PostgreSQL. При запуске приложение применяет новые SQL-миграции, а данные базы живут в томе `postgres_data`. Повторный запуск сидов сохраняет существующие настройки. Сиды создают организатора, «Дело о пропавшем коде» с шестью квестами и пример запуска с попытками.

Если сохранились игры в браузере на том же адресе, админка импортирует пользовательские игры при первом входе. При совпадении идентификатора сохраняются данные сервера.

## Структура и разработка

```text
src/
  client/
    app/           маршруты, оболочка, сессия и HTTP-клиент
    pages/         страницы React Router
    components/    общие UI-компоненты
    features/      редакторы квестов, настройки игр и прогресс
    hooks/         кастомные хуки
    utils/         вспомогательные функции и их тесты
  server/
    auth/          сессии организаторов
    db/            PostgreSQL, миграции и сиды
    games/         настройки игр и маршруты админки
    runs/          запуски, попытки и маршруты игроков
  shared/          типы и параметры квестов без React
```

У каждой страницы, компонента и кастомного хука своя папка. CSS компонента лежит рядом с его TSX. Вспомогательные функции собраны в `src/client/utils`.

Для разработки нужен Node.js 24. При запущенном сервере `npm run dev` поднимает Vite с прокси API на порт 4173. `npm run build` проверяет типы и собирает `dist/index.html` для Express. Открывайте админку по HTTP или HTTPS. Страница игры имеет адрес `/<id>`, редактор — `/<id>/<тип-квеста>`.

При запросе HTML Express проверяет сессию организатора по HTTP-only cookie. В HTML авторизованной страницы он помещает каталог, краткий список игр и конфигурацию открытой игры. React начинает с этих данных. Для страницы списка полные настройки игр не загружаются. Vite в режиме разработки получает те же данные через `GET /api/v1/admin/bootstrap` перед первым рендером.

Миграция `002_catalog.sql` добавляет `quest_catalog` с шаблонами и метаданными и `icon_catalog` с подписями иконок. Новый квест создаётся из серверного шаблона. Настройки существующих игр и снимки уже созданных запусков хранятся отдельно. Тексты интерфейса собраны в русском словаре `src/client/app/messages/ru.ts`.

```sh
npm ci
npm run lint
npm run format:check
npm test
npm run build
```

`npm run format` применяет Prettier. `npm run test:watch` запускает юнит-тесты Vitest в режиме наблюдения. При запуске Express вне Docker задайте `DATABASE_URL`, затем выполните `npm run db:migrate`, `npm run db:seed` и `npm start`.

## API для Android

Версия API задаётся префиксом `/api/v1`. Запросы принимают JSON. Организатор получает токен через `POST /auth/login`, игрок — через код запуска. Передавайте полученный токен в `Authorization: Bearer <token>`.

| Метод и путь после `/api/v1`                     | Назначение                                         |
| ------------------------------------------------ | -------------------------------------------------- |
| `GET /health`                                    | Проверить доступность сервера и базы               |
| `GET, POST /admin/games`                         | Список игр и создание                              |
| `PUT, DELETE /admin/games/:gameId`               | Изменение и удаление игры                          |
| `GET, POST /admin/games/:gameId/runs`            | Список запусков и создание по названию и коду      |
| `GET /admin/games/:gameId/runs/:runId`           | Прогресс и журнал попыток                          |
| `POST /player/runs/join`                         | Вход команды, тело `{ "code": "..." }`             |
| `GET /player/runs/:runId`                        | Задания, состояние и заработанные цифры            |
| `POST /player/runs/:runId/quests/:type/open`     | Зафиксировать время открытия квеста                |
| `POST /player/runs/:runId/quests/:type/attempts` | Отправить `{ "attemptId": "<UUID>", "answer": … }` |

В `answer` передавайте строку для QR, NFC и ответа по фото, массив идентификаторов ячеек для предметов и ёлки либо объект `{ "word": "...", "overlay": 3 }` для трафаретов. Для повтора того же запроса сохраняйте `attemptId`. Ответ содержит статус и, если квест решён, позицию и цифру для замка. Настройки квестов и код копируются в запуск при его создании. В Android выдаётся только информация для игрока.

## Развёртывание

На виртуальной машине с Docker достаточно скопировать проект, задать значения в `.env` и выполнить те же команды Compose. Для доступа извне разместите приложение за HTTPS-прокси и задайте `COOKIE_SECURE=true` в `.env`. По умолчанию порт приложения привязан к loopback, а порт PostgreSQL доступен только внутри сети Compose. Для внешнего PostgreSQL образ приложения принимает `DATABASE_URL`.

В Yandex Cloud для Compose подходит ВМ Compute Cloud. Для запуска через Container Optimized Image заранее соберите и опубликуйте образ, укажите его через `image` в спецификации Compose для ВМ и настройте доступ сервисного аккаунта к реестру. [Руководство Yandex Cloud по ВМ с несколькими контейнерами](https://yandex.cloud/ru/docs/tutorials/container-infrastructure/docker-compose).
