# Бюро квестов

Админка на React и TypeScript, API на Express, база PostgreSQL. Express обслуживает API и веб-сборку с одного адреса.

## Запуск в Docker

Скопируйте `.env.example` в `.env`. Задайте `POSTGRES_PASSWORD` и пароль организатора `ADMIN_PASSWORD`. Для локального примера можно использовать почту `organizer@example.test` и пароль `demo-password`.

```sh
docker compose up --build -d --wait
docker compose exec app npm run db:seed
```

Админка открывается на [127.0.0.1:4173](http://127.0.0.1:4173). Docker Compose ждёт готовности PostgreSQL. При запуске приложение применяет новые SQL-миграции, а данные базы живут в томе `postgres_data`. Повторный запуск сидов сохраняет существующие настройки. Сиды создают организатора, «Дело о пропавшем коде» с шестью квестами и пример запуска с попытками.

Если сохранились игры в браузере на том же адресе, админка импортирует пользовательские игры при первом входе. При совпадении идентификатора сохраняются данные сервера.

## Квесты

В демоигре «Дело о пропавшем коде» шесть улик. Каждый решённый квест открывает одну цифру замка. Порядок квестов в настройках задаёт позиции цифр. Игроки могут проходить задания в любом порядке.

<details>
<summary>Метка на месте преступления</summary>

- **Игроки.** По текстовой подсказке или картинке находят предмет с NFC-меткой и сканируют её.
- **Подготовка.** Добавьте метки в редакторе, отметьте подлинник, задайте лимит попыток и запишите токены на метки как текст NDEF. Админка умеет записывать и проверять метки в браузере с Web NFC. Токены также можно скопировать для отдельного приложения записи.
- **Проверка.** Токен подлинника открывает цифру. Каждая отправка токена настроенной ложной метки расходует попытку. Неизвестный токен попытку не расходует.

</details>

<details>
<summary>Разорванная фотография</summary>

- **Игроки.** Ищут девять частей картинки, собирают пазл и сканируют QR-код на обороте.
- **Подготовка.** Загрузите картинку, выберите размер и способ кадрирования, затем скачайте PDF. Напечатайте его на A4 с двух сторон в масштабе 100% с переворотом по длинному краю. Проверьте совмещение сторон и считывание QR на пробном листе. Разрежьте по сетке 3×3 и спрячьте части.
- **Проверка.** Сервер сверяет считанный токен с токеном улики. После смены токена распечатайте пазл заново.

</details>

<details>
<summary>Три предмета в комнате</summary>

- **Игроки.** Осматривают комнату, ничего не трогая, и выбирают в сетке 3×3 три предмета, которые нашли.
- **Подготовка.** Настройте девять ячеек, подписи и иконки из библиотеки или собственные картинки. Отметьте три правильных предмета и разместите их в комнате.
- **Проверка.** Сервер принимает три разных идентификатора ячеек. Порядок выбора свободный.

</details>

<details>
<summary>Фото до метели</summary>

- **Игроки.** Сравнивают старый снимок с комнатой и вводят название предмета, который исчез.
- **Подготовка.** Сфотографируйте комнату с предметом, загрузите снимок и уберите предмет перед началом. Перечислите допустимые названия через запятую.
- **Проверка.** Сервер принимает один из заданных вариантов. При сравнении учитывается нормализация регистра, пробелов и букв «е» и «ё».

</details>

<details>
<summary>След на ёлке</summary>

- **Игроки.** Разгадывают подсказку, сверяются с игрушками на ёлке и нажимают четыре символа на клавиатуре 3×3 в заданном порядке.
- **Подготовка.** Настройте девять иконок игрушек и укажите правильную последовательность из четырёх разных ячеек. Сформулируйте загадку так, чтобы она подсказывала и выбор игрушек, и их порядок.
- **Проверка.** Сервер сравнивает и набор ячеек, и последовательность нажатий.

</details>

<details>
<summary>Два слоя снега</summary>

- **Игроки.** Один остаётся за дверью с двумя карточками без подсказки об их порядке. На одной — штрихи букв первой половины слова, на другой — второй. Второй игрок перебирает восемь накладок и показывает их через окно или в проёме. Передавать реквизит через порог нельзя.
- **Подготовка.** Задайте слово из 4–12 русских или латинских букв с чётной длиной. Скачайте PDF на три листа A4 и напечатайте в масштабе 100%. Перенесите штрихи и рамки на прозрачный пластик, а номера — на восемь длинных накладок. На первом листе есть контрольное слово для организатора.
- **Проверка.** Только подлинная накладка достраивает слово на обеих карточках. Игроки вводят слово и номер подлинника. В новом комплекте ложные накладки смешивают переставленные штрихи букв слова со штрихами случайных букв, которых в нём нет. Кнопка «Новый комплект» меняет раскладку и номер подлинника.

</details>

## Структура и разработка

```text
src/
  client/
    app/           маршруты, оболочка, сессия и HTTP-клиент
    pages/         страницы React Router
    components/    общие UI-компоненты
    features/      редакторы квестов, настройки игр и прогресс
    hooks/         кастомные хуки
    utils/         вспомогательные функции и их тесты
  server/
    auth/          сессии организаторов
    db/            PostgreSQL, миграции и сиды
    games/         настройки игр и маршруты админки
    runs/          запуски, попытки и маршруты игроков
  shared/          типы и параметры квестов без React
```

У каждой страницы, компонента и кастомного хука своя папка. CSS компонента лежит рядом с его TSX. Вспомогательные функции собраны в `src/client/utils`.

Для разработки нужен Node.js 24. При запущенном сервере `npm run dev` поднимает Vite с прокси API на порт 4173. `npm run build` проверяет типы и собирает `dist/index.html` для Express. Открывайте админку по HTTP или HTTPS. Страница игры имеет адрес `/<id>`, редактор — `/<id>/<тип-квеста>`.

При запросе HTML Express проверяет сессию организатора по HTTP-only cookie. В HTML авторизованной страницы он помещает каталог, краткий список игр и конфигурацию открытой игры. React начинает с этих данных. Для страницы списка полные настройки игр не загружаются. Vite в режиме разработки получает те же данные через `GET /api/v1/admin/bootstrap` перед первым рендером.

Миграция `002_catalog.sql` добавляет `quest_catalog` с шаблонами и метаданными и `icon_catalog` с подписями иконок. Новый квест создаётся из серверного шаблона. Настройки существующих игр и снимки уже созданных запусков хранятся отдельно. Тексты интерфейса собраны в русском словаре `src/client/app/messages/ru.ts`.

```sh
npm ci
npm run lint
npm run format:check
npm test
npm run build
```

`npm run format` применяет Prettier. `npm run test:watch` запускает юнит-тесты Vitest в режиме наблюдения. При запуске Express вне Docker задайте `DATABASE_URL`, затем выполните `npm run db:migrate`, `npm run db:seed` и `npm start`.

<details>
<summary>Контекст для следующей сессии с агентом</summary>

- **Локальная проверка.** Начните с [правил проекта](AGENTS.md) и команд выше. При использовании Colima с отдельным Compose вызовите `colima start`, затем `DOCKER_CONTEXT=colima docker-compose up --build -d --wait`. Проверка API и PostgreSQL — `GET /api/v1/health`. Для проверки интерфейса откройте [прогресс демоигры](http://127.0.0.1:4173/detective-demo/progress). В начальных демоданных у «Команды № 1» решено три квеста из шести.
- **Веб-админка.** Express отдаёт сборку из `dist/`. После изменений для проверки через Docker пересоберите образ, а для быстрой разработки держите Express запущенным и откройте адрес, который выводит `npm run dev`. Vite направляет запросы API на `QUEST_API_TARGET`, по умолчанию `http://127.0.0.1:4173`.
- **Навигация и данные.** Главная показывает игры. Маршруты React Router имеют вид `/<id>`, `/<id>/<тип-квеста>` и `/<id>/progress`. Серверный bootstrap передаёт каталог, краткий список и открытую игру. Клиент заполняет этими данными TanStack Query, каталог доступен через React Context. Черновики редактирования хранятся в компоненте. Прогресс выбранного запуска опрашивается каждые 10 секунд.
- **Изменения механики.** Общие типы лежат в [quests.ts](src/shared/quests.ts). Шаблоны хранятся в `quest_catalog` и читаются через [catalogStore.ts](src/server/games/catalogStore.ts). При изменении квеста сверяйте [схему настроек](src/server/games/gameSchema.ts), [проверку готовности](src/server/runs/playableQuest.ts), [проверку ответа](src/server/runs/answers.ts), выдачу данных игроку и редактор в `src/client/features/quests/`. Изменения каталога оформляйте новой SQL-миграцией в `src/server/db/migrations/`.
- **Контракт игрока.** Сервер сохраняет настройки, позиции и цифры как снимок на момент запуска. Изменения игры применяются к новым запускам. При повторе запроса попытки сохраняйте исходный `attemptId`. В ответах API игрока оставляйте только публичные параметры квеста и уже заработанные цифры.
- **Совместимость трафаретов.** [stencilStrokes.ts](src/client/utils/stencilStrokes.ts) строит штрихи по сохранённым `strokeSeed` и `strokeVersion`. Старые версии нужны для повторной печати уже подготовленных комплектов. Новый алгоритм включается для новых квестов и по кнопке «Новый комплект». В [stencil.ts](src/client/utils/stencil.ts) предпросмотр и экспорт используют одни и те же слои.

</details>

## API для Android

Версия API задаётся префиксом `/api/v1`. Запросы принимают JSON. Организатор получает токен через `POST /auth/login`, игрок — через код запуска. Передавайте полученный токен в `Authorization: Bearer <token>`.

| Метод и путь после `/api/v1`                     | Назначение                                         |
| ------------------------------------------------ | -------------------------------------------------- |
| `GET /health`                                    | Проверить доступность сервера и базы               |
| `GET, POST /admin/games`                         | Список игр и создание                              |
| `PUT, DELETE /admin/games/:gameId`               | Изменение и удаление игры                          |
| `GET, POST /admin/games/:gameId/runs`            | Список запусков и создание по названию и коду      |
| `GET /admin/games/:gameId/runs/:runId`           | Прогресс и журнал попыток                          |
| `POST /player/runs/join`                         | Вход команды, тело `{ "code": "..." }`             |
| `GET /player/runs/:runId`                        | Задания, состояние и заработанные цифры            |
| `POST /player/runs/:runId/quests/:type/open`     | Зафиксировать время открытия квеста                |
| `POST /player/runs/:runId/quests/:type/attempts` | Отправить `{ "attemptId": "<UUID>", "answer": … }` |

В `answer` передавайте строку для QR, NFC и ответа по фото, массив идентификаторов ячеек для предметов и ёлки либо объект `{ "word": "...", "overlay": 3 }` для трафаретов. Для повтора того же запроса сохраняйте `attemptId`. Ответ содержит статус и, если квест решён, позицию и цифру для замка. Настройки квестов и код копируются в запуск при его создании. В Android выдаётся только информация для игрока.

## Развёртывание

На виртуальной машине с Docker достаточно скопировать проект, задать значения в `.env` и выполнить те же команды Compose. Для доступа извне разместите приложение за HTTPS-прокси и задайте `COOKIE_SECURE=true` в `.env`. По умолчанию порт приложения привязан к loopback, а порт PostgreSQL доступен только внутри сети Compose. Для внешнего PostgreSQL образ приложения принимает `DATABASE_URL`.

В Yandex Cloud для Compose подходит ВМ Compute Cloud. Для запуска через Container Optimized Image заранее соберите и опубликуйте образ, укажите его через `image` в спецификации Compose для ВМ и настройте доступ сервисного аккаунта к реестру. [Руководство Yandex Cloud по ВМ с несколькими контейнерами](https://yandex.cloud/ru/docs/tutorials/container-infrastructure/docker-compose).
